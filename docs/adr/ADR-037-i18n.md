# ADR 037: Internationalization

## Status

Accepted — 2026-11-11

## Context

The UI and documentation are English-only; the audience is not. Strings are
inline in Vue templates, so a German deployment currently needs a fork. ADR-001
prefers a small dependency surface, and the roadmap calls for a CI check that
catches missing keys.

## Decision

- **`vue-i18n` v11** (Composition API, legacy: false) is the one new dependency.
  It is the de-facto Vue 3 library, supports pluralization/date-number
  formatting, and is tree-shakeable in the Vite build.
- Messages live in `src/i18n/messages/{en,de}.json`; `en` is the fallback and
  the source of truth. Keys are nested by surface (`nav`, `header`, `login`, …).
- **Locale is persisted** in `localStorage` (`vrt-locale-v1`), defaults to
  English, and sets `document.documentElement.lang`. A header `LocaleSwitcher`
  changes it without reload.
- **CI check**: `pnpm --filter frontend i18n:check` parses both JSON files,
  flattens the key paths and fails on missing/extra/empty translations. It is a
  key-parity check, not a hardcoded-string linter.
- Extraction starts with the shared shell (sidebar, header), login and the
  common navigation surfaces; domain pages follow incrementally. English stays
  the default so existing tests and screenshots are stable.

## Alternatives considered

- **Hand-rolled dictionary**: no pluralization/date-number formatting and no
  established tooling; rejected.
- **`@nuxt/i18n` / `vue-i18next`**: either Nuxt-specific or a second runtime
  style; `vue-i18n` matches the Composition API and test setup.
- **URL-prefixed locales** (`/de/...`): deep links and router tests would all
  change; a persisted preference is enough for a self-hosted single-tenant app.
- **Full extraction in one pass**: too risky/noisy for a working UI; incremental
  extraction with a parity check keeps every commit shippable.

## Consequences

- A new UI string must be added to both JSON files or `i18n:check` fails.
- Untranslated domain pages remain English until extracted; the fallback keeps
  them functional.
- Dates/numbers stay locale-neutral until the extraction reaches those views;
  `vue-i18n`'s `d()`/`n()` are the target for that pass.
